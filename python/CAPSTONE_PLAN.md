# DATA120 Capstone Plan

**Working title:** Identifying unusual repeat-parking patterns from intermittent, manually collected observations

## 1. Background and objective

The existing ParkingPatrol application collects staff observations using Google Forms, Google Sheets, and Apps Script. DATA120 will use Python to study the observations separately, not replace production operations.

**Research question:** Can observation-based features distinguish ordinary and unusual repeat-sighting patterns well enough to improve staff review prioritization?

**What the model does not know:** Whether a driver is a customer; when a vehicle entered or left; whether it stayed between checks; whether a parking policy was actually breached.

## 2. Proposed unit of analysis

Start with **one vehicle per observation window**, such as the previous 30 days, and a clearly defined cutoff date. Use pseudonymous IDs that cannot be reversed from files committed to GitHub.

Candidate features, only if supported by source data:
- Number of sightings
- Number of distinct observed days
- Number of completed checks in the relevant area (observation coverage)
- Number of areas observed
- Number of weeks with sightings
- Time-of-day or day-of-week distribution
- Gap between first and last sighting (not parking duration)
- Share of *completed checks* in which the vehicle was observed within the same area/window

Use time windows ending **before** each evaluation date; avoid data leakage.

## 3. ML strategy

1. **Explore:** Plot sightings by date, hour, area, and checking frequency. Confirm coverage and missing data.
2. **Baseline:** Simple transparent rule, e.g. flag 3+ distinct sighting dates in a 30-day window. This is a review signal, not proof.
3. **If independently verified outcome labels are available:** Compare a simple supervised classifier (for example logistic regression or a decision tree) against the rule baseline. Use only labels based on external review, not labels generated by the same rule being tested.
4. **If no trustworthy labels are available:** Try unsupervised clustering or anomaly detection, clearly describing it as unusual-pattern discovery. Do not report offender-classification accuracy.
5. **Evaluate:** Split chronologically rather than randomly across repeat vehicle records; compare against checking coverage, and inspect false alarms. For supervised work consider precision, recall, confusion matrix, and class balance. For unsupervised work emphasize stability and human-reviewed usefulness rather than unsupported accuracy claims.
